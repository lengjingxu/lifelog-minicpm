# 运行与架构细节

## 数据表

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `assets` | 登记过的每个媒体文件 | id(path+size+mtime 哈希)、path、taken_at、day、lat/lon |
| `captions` | 每张图的模型理解结果 | model、model_version、prompt_version、caption/scene/people/place/activity/mood/tags、ocr_text、status |
| `days` | 「一天的样子」 | day、photo_count、described、tags、hour_histogram |
| `events` | 「生活片段」 | start_day、end_day、title、summary、tags、photo_count |
| `profile` | 生活画像 | key、value（summary / stats / top_tags…）、evidence、updated_at |
| `runs` | 每次流水线的执行记录 | stage、model、started_at、finished_at、stats |

`captions` 主键是 (asset_id, model, prompt_version)：换模型或换 prompt 不会覆盖旧结果，
可以随时对比不同模型对同一批照片的理解差异。

## 三级模型分工

1. **MiniCPM-V-4.7-1B（Q8, 1.1 GB）** — 全量粗筛。每张图一次请求，
   Apple Silicon 实测约 1.5 秒/张，5 万张的库可在数小时内跑完。
2. **MiniCPM-OCR-1.0（Q8, 0.8 GB）** — 只对需要的图抽图内文字，
   结果写回同一条 caption 记录的 `ocr_text` 字段。
3. **MiniCPM-V-4.5-8B（Q4_K_M, 5.0 GB）** — 深度理解：重点照片的细粒度解读，
   以及最终「生活画像」的写作。

## 幂等与断点续跑

- `ingest`：按 path+size+mtime 生成资产 id，重复执行只补新增与变化。
- `caption`：只有 `status='ok'` 的记录才视为完成，中断后重跑自动接着跑。
- `aggregate`：纯统计，无模型调用，可反复重建。
- `profile`：重新生成画像会覆盖同名 key。

## 隐私

- 推理全部走本机 llama.cpp，照片以本地 data URL 形式发给 127.0.0.1 的服务进程。
- 不调用任何云端视觉 API；命令行与 MCP 都没有对外网络请求。
- 小米云盘同步只读云端，只写本地目录，下载按块 sha1 + 整文件 sha1 双重校验。
