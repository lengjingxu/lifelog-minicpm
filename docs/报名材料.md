## 二、作品介绍（可直接粘贴，约 700 字）

**拾光 LifeLog** 是一个完全跑在本机的「生活记忆引擎」，目标只有一句话：让 AI 随时了解我的生活。

人的相册里已经藏着大量生活信息，但它们是散点：一张图、一句话，任何 AI 都读不懂。
拾光把这条链路补齐——先从小米云盘把相册同步回本地（只读云端，不删除任何文件），
再用本地部署的 MiniCPM 视觉模型逐张读懂照片，产出结构化描述（场景、人物、地点线索、
正在进行的事、氛围、标签）；随后把散点聚合成「一天的样子」与一段段「生活片段」，
最终生成一份可以被直接阅读的**生活画像**：我的作息节奏、常去的场景、社交与独处的比例、
兴趣与活动、情绪基调、季节与时段偏好。

与「看图说话」demo 的区别在于三点。第一是**全部本地**：模型用 openbmb 官方 GGUF 权重，
llama.cpp + Metal 加速，照片与描述一次都不出本机，也不依赖任何云端视觉 API。
第二是**可复用**：最后一步把这份记忆通过 MCP 工具暴露给任意 AI 助手，
装上以后就能直接问「我上个月常去哪里」「我一个人在家的时候都在做什么」，
答案来自带日期和场景的真实证据，不是编的。第三是**工程完整度**：
同步有断点续传与 sha1 校验，识别有 prompt 版本化与可续跑的缓存，
聚合是幂等的纯统计，画质与数据都留在本地 SQLite 里。

**为什么是 MiniCPM**：MiniCPM-V-4.7-1B 在 Apple Silicon 上实测约 1.5 秒/张，
意味着一部 5 万张的私人相册可以在数小时内跑完全量识别——
这让「全库理解」从演示变成日常。
MiniCPM-OCR-1.0 专门负责截屏、订单、票据、路牌里的文字，
补上相册里最容易被忽略但最有信息量的那部分；MiniCPM-V-4.5-8B 则用来做
重点照片的深度解读与最终画像写作。

一句话总结：拾光把相册从「一堆图片」变成「一份关于这个人的、可检索可追问的生活档案」，
而这件事从头到尾没有离开过这台电脑。

## 三、技术架构

```
小米云盘相册 (i.mi.com gallery API, RC4 解密)
        │  sync_xiaomi.py   只读云端 / sha1 校验 / 断点续传
        ▼
本地相册目录  ──ingest.py──►  assets 表（路径、拍摄时间、GPS、类型）
                                      │
                     caption.py / ocr.py │  MiniCPM（llama.cpp 本地推理）
                                      ▼
                          captions 表（结构化描述 + 标签 + 图内文字）
                                      │
                        aggregate.py │  纯统计、幂等
                                      ▼
                    days（每天的样子） / events（生活片段） / profile（生活画像）
                                      │
              query.py ────────────────┴──────────► CLI / MCP Server / 本地网页
```

技术要点

- **模型全部本地**：MiniCPM-V-4.7-1B（1.1 GB）、MiniCPM-V-4.5-8B（5.0 GB）、
  MiniCPM-OCR-1.0（0.8 GB），llama.cpp 0.7.0 + Metal，OpenAI 兼容接口。
- **成本可预期**：1B 负责全量粗筛，OCR 只跑需要抽文字的图，8B 只跑重点，
  三级分工让「全库理解」在 16 GB 内存的笔记本上跑得动。
- **工程可复用**：prompt 版本化 + 逐张缓存 → 换模型、换 prompt 都能断点续跑；
  聚合与画像生成幂等；MCP Server 无第三方依赖，40 行协议实现。
- **隐私**：默认不出网；同步只读云端；本地 SQLite 单文件、随项目走。

| 活动要求 | 本项目的对应实现 |
| --- | --- |
| 本地 MiniCPM 实质参与理解 | caption.py 全部描述由本地 MiniCPM-V 产出，无任何云端 API |
| 实质参与识别 | MiniCPM-OCR-1.0 承担图内文字识别，结果写回同一条记录 |
| 实质参与工具选择 | 同一套模型按任务分流：1B 全量粗筛 / 4.5-8B 深度解读与写作 / OCR 抽字 |
| 实质参与结果检查 | 解析失败进「待复核」状态；同步按块 sha1 与整文件 sha1 双重校验 |
| 按目标整理图片资料 | 标签体系 17 类 + 场景/地点/人物/活动四维结构化 |
| 根据分类结果调整分组、核对遗漏 | aggregate.py 按天与连续拍摄串成生活片段；覆盖率与「未识别」计数可直接核对遗漏 |
| 交付整理结果 | 生活画像 + 生活片段表 + MCP 可查询接口 + 本地网页 |

## 五、5 分钟演示脚本

1. **0:00–0:40 痛点**：展示相册里 7 万张照片，问「AI 怎么知道我这半年过得怎么样」。
2. **0:40–1:20 同步与入库**：`lifelog sync` 拉取云端相册 → `lifelog ingest` 登记资产，
   展示 SQLite 里的 assets 表与拍摄时间/GPS。
3. **1:20–2:30 识别**：`lifelog caption --model minicpm-v-4.7-1b` 现场跑几张，
   展示结构化 JSON（场景/人物/地点/活动/标签），说明断点续跑与缓存。
4. **2:30–3:20 文字层**：`lifelog ocr --model minicpm-ocr-1.0` 抽一张订单截屏的文字，
   展示它写回同一条记录。
5. **3:20–4:20 聚合与画像**：`lifelog aggregate` → `lifelog profile --model minicpm-v-4.5-8b`，
   展示「一天的样子」「生活片段」和最终生活画像。
6. **4:20–5:00 AI 接入**：在任意 MCP 客户端里问「我上个月常去哪」，现场调
   `lifelog_ask`，答案带日期与场景证据；再展示本地网页相册与画像页。
