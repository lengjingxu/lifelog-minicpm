## 一、作品介绍（可直接粘贴，约 800 字）

**拾光 LifeLog** 是一个完全跑在本机上的「人生回顾引擎」，它回答一个问题：
**一个人十年的相册，能不能被 AI 真的读懂？**

痛点很普遍：十年小米手机，攒下 29294 张照片、几百个 G。不是不想回忆，是翻不动——
重复的照片、找不到的那一张、记不清是哪年的哪次旅行。删吧，怕删掉真的重要；
不删吧，它就一直在那里，越来越沉。

拾光把这条链路跑通了，全流程四步：

1. **同步** · 从小米云盘把相册拉回本地（只读云端，RC4 解密，sha1 双重校验，
   支持增量，第二次跑同一区间 2.5 秒内完成）；
2. **识别** · MiniCPM-V-4.7-1B 逐张看图，产出结构化 JSON：场景、人物、地点、
   活动、氛围、标签。实测 Apple M6 / 16GB 上 **1.2 张/秒（4 并发）**，
   全库 29,294 张单轮约 6-7 小时，支持断点续跑；
3. **聚合** · 纯统计把这些描述聚成「一天的样子」和 41 段「生活片段」，
   算出独处占比 82%、出门高峰在下午 16-17 点、带孩子的日子集中在周末这类事实；
4. **叙事** · MiniCPM-V-4.5-8B 把事实写成**三种视角的中文叙事**——
   「你的这些年」「给十年后的你」「给家人的信」——以及一份四段式的**自我画像**
   （最爱拍什么 / 性格底色 / 没拍下来的那部分 / 三条建议）。

与看图说话 demo 的区别有三点。**一是全部本地**：模型用 openbmb 官方 GGUF，
llama.cpp + Metal 加速，照片与描述一次都不出本机。**二是事实约束**：模型只能引用
程序算出的「事实白名单」里的数字，示例输出——「2026 年 9 月 26 日，一个小女孩坐在
装饰有兔子玩偶的户外场景里，表情很平静。那是你这一年唯一一次带她出门。上一次，是
2024 年」——每个数字都可核对。**三是可对话**：整份记忆通过 MCP 暴露给任意 AI 助手，
装上就能问「我上个月常去哪」「我一个人待着的时候都在做什么」，答案带着日期和场景证据。

一句话总结：拾光把相册从「一堆图片」变成「一份关于这个人的、可检索、可追问、
有情感的人生档案」，而这件事从头到尾没有离开这台电脑。

## 二、为什么选 MiniCPM（选型对比）

这是一份**本地优先**的项目，模型的第一硬指标是：能在一台 16GB 内存的消费级电脑上、
完全离线地跑完几万张照片。

| 候选模型 | 最小可用体量 | 16GB Mac 可跑 | 逐张吞吐 | 结论 |
| --- | --- | --- | --- | --- |
| GPT-4V / Claude | — | 需上传 | — | 隐私红线，直接排除 |
| **MiniCPM-V-4.7-1B** | **1.1 GB (Q8)** | **可用** | **约 1.2 张/秒** | **主识别** |
| MiniCPM-V-4.5-8B | 5.0 GB (Q4) | 可用 | 约 40 s/篇 | **深度理解与写作** |
| MiniCPM-V-4.7-35B-A3B | 14.5 GB (IQ3) | 不可用 | — | 16GB 装不下 |

选它的三个理由：**体积**（Q8 仅 1.1 GB，是 16GB 机器上唯一能与系统共存连跑几小时的
档位）；**速度**（Metal 加速下 1.2 张/秒，5 万张半天跑完）；**官方 GGUF**（openbmb
直接发布，含 1B / 4.5-8B / OCR 三个档位，无需自行转换）。

## 五、对照活动要求自评

| 活动要求 | 本项目的对应实现 |
| --- | --- |
| 本地 MiniCPM 实质参与理解 | caption.py 全部描述由本地 MiniCPM-V 产出，无云端 API |
| 实质参与识别 | MiniCPM-OCR-1.0 承担图内文字识别，写回同一条记录 |
| 实质参与工具选择 | 1B 全量粗筛 / 4.5-8B 深度解读与写作 / OCR 抽字，三级分流 |
| 实质参与结果检查 | 解析失败进「待复核」；同步按块 sha1 + 整文件 sha1 双校验 |
| 按目标整理图片资料 | 17 类标签 + 场景/地点/人物/活动四维结构化 |
| 根据分类调整分组、核对遗漏 | aggregate.py 按天与连续拍摄串成片段；覆盖率与未识别计数可直接核对 |
| 交付整理结果 | 生活画像 + 三种叙事 + 片段表 + MCP 接口 + 本地网页 |
