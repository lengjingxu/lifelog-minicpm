# 拾光 Mac 客户端 · 产品与技术方案 v1

> 用途：先确认 UI 与信息架构，再交给开发实现。  
> 配套评审页：`docs/ui-review.html`（含 4 张 UI 示意稿）

---

## 1. 目标与边界

**一句话**：给「拾光」做一个本地优先的 macOS 相册客户端——直接吃现有 SQLite 库，把 AI 打标结果变成可浏览、可检索、可筛选的相册体验，不依赖任何云端服务。

**阶段一的目标（可验收）**

| 指标 | 目标值 | 验证方式 |
|---|---|---|
| 冷启动到首屏 | < 400ms（239 条）/ < 1s（10 万条） | 打点计时 |
| 滚动 | 60fps，无白块 | 手动滚动 + 录制帧率 |
| 搜索响应 | < 80ms（本地 239 条） | 输入即出结果 |
| 详情大图 | < 200ms（本地） | 点击到图出现 |
| 断网可用 | 完全可用 | 关 WiFi 验一遍 |

**不做的事（明确排除）**

- 不做云同步、不做账号体系、不做服务端
- 不做图片编辑（裁剪/调色/修图）——后续可接 Core Image
- 不做移动端（iOS 另立项）
- 阶段一不实现端侧向量检索（先做全文 + 结构化筛选，见 §6.4）

## 2. 现状与引用

**已有的底层能力（本项目直接复用）**

| 能力 | 位置 | 说明 |
|---|---|---|
| 数据模型 | `lifelog/db.py` | SQLite WAL，六张表 |
| 小米导入 | `lifelog/sync_xiaomi.py` | token 来自 `~/.xiaomi-token/token.mjs`（CDP 取态），RC4 + secure_key 解密 |
| AI 识别 | `lifelog/caption.py` + `models.py` | 本地 llama.cpp（默认 8077），MiniCPM GGUF + mmproj，输出结构化 JSON |
| 缩略图 | `lifelog/web.py:43` | 现为按需生成，360px，缓存到 `data/thumbs/` |
| 当前 UI | `lifelog/web.py` | `http.server` + 手写 HTML，仅作参考 |

**数据契约（客户端必须按这个读，不要改表）**

```
assets(id, path, size, mtime, taken_at, day, lat, lon, kind, created_at)
captions(asset_id, model, model_version, prompt_version, caption, scene,
         people, place, activity, mood, tags(JSON数组), ocr_text, status, created_at)
days(day, photo_count, described, tags, summary, hour_histogram, updated_at)
events(id, start_day, end_day, title, summary, tags, photo_count)
profile(key, value, evidence)
runs(id, stage, model, started_at, finished_at, stats)
```

一个 asset 可能有多条 caption（不同模型/提示词版本）。**客户端取 `created_at` 最新的一条**，不要做 JOIN 聚合。

**设计参考**

| 参考 | 借什么 | 不借什么 |
|---|---|---|
| Sooty（Mac 资产管理器） | 网格密度、即时筛选、克制的深色质感（配色改为黑红） | 多格式（字体/3D/PDF）、插件体系 |
| Apple Photos | 时间线分组、单张详情的克制感 | iCloud 相关概念 |
| Eagle | 标签体系与库管理 | 卡片式重 UI |
| Immich | 搜索与筛选的交互顺序 | 服务端架构 |

## 3. 设计系统

**色板**（黑红，深色为唯一主题，阶段一不做浅色）

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#08080A` | 窗口底色（近黑，带极淡红光晕） |
| `--bg-elevated` | `rgba(255,255,255,0.045)` | 卡片、输入框 |
| `--line` | `rgba(255,255,255,0.08)` | 1px 描边 |
| `--text` | `#F2F1EE` | 主文本 |
| `--text-dim` | `rgba(242,241,238,0.62)` | 次级文本 |
| `--text-faint` | `rgba(242,241,238,0.38)` | 说明、计数 |
| `--accent` | `#FF4A4A` | 选中、强调、主按钮、进度条 |
| `--accent-soft` | `rgba(255,74,74,0.14)` | 标签底、选中底 |
| `--accent-line` | `rgba(255,74,74,0.28)` | 强调描边 |

**用色规则**：红色只出现在「选中态 / 进度条 / 主按钮 / 错误与失败数」四处，正文、图标、边框一律中性色；红色不用于长文本，避免刺眼。

**字体**：SF Pro Text / PingFang SC；标题 15px/600，正文 13px/400，说明 11.5px，计数 11px（tabular-nums）。

**几何**：圆角 10px（缩略图）/ 12–14px（面板）/ 999px（药丸）；间距基线 4px，常用 6/8/12/16/20/28。

**动效**：hover 180ms `cubic-bezier(.2,.8,.3,1)`；面板进入 180ms fade+4px 位移；不做弹跳与夸张缓动。

**网格密度**：默认 6 列（1360px 窗口），列最小 160px，间距 10–12px；提供「舒适/紧凑」两档（⌘+ / ⌘-）。

## 4. 页面与功能

### P1 主库（默认页）
- **目的**：一眼看到全部照片，并知道库有多大、跨度多久。
- **结构**：左侧 232px 侧边栏 + 顶部工具栏 + 主网格。
- **展示信息**：标题（当前视图名）、副标题（`N 张 · 起止年份`）、搜索框（⌘K）、视图切换、网格。每张缩略图 hover 出底部渐变 + 一行 AI 描述；左上角小徽标标注类型（视频/截图/实况）。
- **侧边栏**：品牌区 → 导航（全部照片 / 时间线）→ 标签（按数量降序，显示计数）→ 人物 / 地点（折叠，默认展开前三）→ 底部库信息（条数、占用、DB 路径的 tooltip）。
- **交互**：单击选中，双击/回车进详情；⌘点击多选，Shift 范围选；右键出菜单（在 Finder 中显示 / 复制描述 / 重新识别 / 加入相册）。
- **空状态**：无数据时给「导入小米相册」与「扫描本地文件夹」两个入口，不要空白页。

### P2 详情
- **目的**：看大图 + 读到 AI 对这张照片的全部理解，并能立刻继续操作。
- **结构**：左侧大图（最大 100% 高，居中，圆角 6px，重投影），右侧 340px 检查器。
- **展示信息**：AI 描述（2–3 行）、键值对（时间 / 场景 / 人物 / 活动 / 氛围 / 地点 / 相机参数（有则显示））、标签药丸（可点击 → 跳筛选）、图内文字（OCR，最多 6 行可滚动）、底部操作（重新识别 / 加入相册 / 导出 / 在 Finder 中显示）。
- **交互**：← → 切上一张/下一张；Esc 关闭；空格回到网格；拖拽图片可导出。
- **加载**：先显示缩略图（模糊放大）再换原图，避免白屏。

### P3 搜索与筛选
- **目的**：用自然语言或标签，在 10 万张里 3 秒内找到目标。
- **结构**：顶部搜索框 + 下方筛选药丸行 + 结果网格 + 排序说明。
- **展示信息**：搜索词、命中数、生效的筛选条件（每个可单个移除）、排序方式（相关度/时间）、每张结果右下角显示匹配置信度。
- **交互**：输入 200ms 防抖；⌘K 聚焦；输入 `/` 进入标签补全；筛选条件可叠加，点标签即加条件。
- **搜索范围**（阶段一）：caption / tags / scene / place / ocr_text / 文件名。空结果时给「放宽条件」建议（去掉时间/人物）。

### P4 时间线
- **目的**：按时间回看，像翻日记。
- **结构**：按「月」分组，每组一个粘性小标题（2023 年 10 月 · 42 张），组内网格。
- **展示信息**：月标题、张数、当月有事件时显示事件名（来自 `events` 表）。
- **交互**：右侧滚动条悬停显示月份索引，可直接跳转。

### P5 分类浏览（标签 / 人物 / 地点）
- **目的**：按 AI 打标结果浏览，而不是按文件夹。
- **结构**：顶部是大分类卡（场景 12 类 / 人物 5 类 / 地点 8 类），点进去是该类的照片网格。
- **展示信息**：每类显示代表图（取该类最新一张）+ 名称 + 数量。

### P6 导入与识别
- **目的**：让长任务可见、可暂停、可估算剩余时间。
- **结构**：磨砂弹窗，三块：小米云导入 / AI 识别打标 / 统计。
- **展示信息**：已导入/总数、进度条、剩余时间、暂停按钮；识别速度（张/秒）、剩余时间、正在处理的三张缩略图；已打标 / 待处理 / 失败三列统计。
- **交互**：可「后台运行」，关闭弹窗不中断任务；失败项可「重试全部失败」。

### P7 设置
- **目的**：让用户能修数据源、换模型、重建缓存。
- **展示信息**：库路径与大小（只读展示 + 更换）、模型列表与当前选择、缩略图缓存大小与「重建」、小米账号登录态（已登录/过期）、快捷键说明。

### P8 整理视图（AI 归位过程）
- **目的**：把「AI 识别」从一条进度条变成看得懂的过程——一大堆杂乱照片，在眼前被归到该去的地方。
- **三个状态**
  1. **待整理**：画布上照片随机堆叠（旋转 ±8°、互相遮挡），顶部只有一个「开始整理」，右上角显示「待整理 N 张 · 预计 M 分钟」。
  2. **整理中**：画布右侧生成 N 个归位区（按标签/场景），每张照片识别完就从堆里飞出、落进对应区域；飞行拖一条 60–120ms 的淡红轨迹。顶部 HUD 实时显示：**速度（张/秒）、已整理/总数、剩余时间、暂停**。
  3. **完成**：四张分组卡（名称 · 数量 · 3×2 代表图），底部「查看相册」「撤销整理」。
- **必须展示的信息**：当前速度、已处理/总数、剩余时间、正在识别的标签、失败数。速度是持续可见的，不是只在结束时给一个总数。
- **交互**：可暂停/继续；点任意分组可提前查看；完成前只做**内存预演**，点「查看相册」才落库，撤销即丢弃。
- **性能预算**：动画 60fps；**模型吞吐与动画必须解耦**——每识别完一张推一条事件进队列，动画按自己节奏消费，宁可动画慢一点也不能掉帧；同屏最多 3 张同时飞行，其余排队。
- **异常**：模型没加载/额度用尽时停在原堆并说明原因；单张失败进「未归类」堆，不阻塞整体。

| 键 | 行为 |

- 任何列表操作不允许同步阻塞主线程 > 16ms

## 6. 技术方案

### 6.1 架构

```
Tauri 2 应用
├── 前端 React 19 + TS + Vite 8（WebView 渲染，不引入 UI 框架，自写 CSS 设计令牌）
└── Rust 后端（tauri command）
    ├── 只读打开 lifelog.sqlite（SQLITE_OPEN_READ_ONLY + busy_timeout）
    ├── 缩略图/原图走 asset protocol（convertFileSrc），不经 IPC
    └── 长任务：spawn Python sidecar（lifelog CLI），读 stdout 进度事件
```

**原则**：客户端**只读**数据库；所有写入（导入、打标、改标签）都通过调用 Python 侧完成，避免两边同时写导致 WAL 冲突。

### 6.2 IPC 契约（阶段一实现这四个）

```ts
library_stats() -> { assets, captions, days, events, first_day, last_day, db_path }
query_assets({ query?, tag?, scene?, kind?, day_from?, day_to?, limit, offset }) -> Asset[]
facets() -> { tags: [name,count][], scenes, people, months }
health() -> { data_dir, db_exists }
```

`Asset` 字段：`id, path, thumb, original, day, taken_at, kind, caption, scene, people, place, activity, mood, tags[], ocr_text`。

### 6.3 缩略图策略（必须改）

现状是按需生成（`web.py:43`），首次滚动 10 万张会逐张解码 HEIC，必卡。

- 导入时预生成两级：`thumbs/{id}.jpg`（360px，网格用）、`thumbs/full/{id}.jpg`（1600px，详情用）
- 用 macOS `ImageIO` 或 `sips` 批量生成，后台低优先级队列
- 生成失败的图用占位符 + 重试一次

### 6.4 搜索实现

- 阶段一：SQL `LIKE` + 标签 JSON 包含（当前做法），239 条下 < 5ms
- 阶段二（>5000 条时）：建 FTS5 虚表覆盖 `caption / tags / scene / place / ocr_text`，`content=sync` 跟随主表
- 阶段三：端侧向量（MiniCPM 文本嵌入或 CLIP），实现「语义相似」而非仅关键词

### 6.5 模型与长任务（复用现有实现，不要另起一套）

主仓库已经有识别现场：`lifelog/recognize.py`。

- `SimSession`：用库里已有描述回放，按真实测速节奏（4 并发，单张中位 ~3.3s，约 1.2 张/秒）模拟识别，**不需要模型**——开发期就用它
- `LiveSession`：真实调 `run_caption`（llama.cpp 在位后启用）
- 事件流：内存 ring buffer，前端按游标拉 `GET /api/live/events?cursor=N`，`state()` 已给出 `rate`（张/秒）、`done_count`、`total`、`status`

所以桌面端**不要新造事件协议**：Rust 侧起 `lifelog serve`，前端轮询同一组 `/api/live/*` 接口即可。整理视图的「速度 / 已整理 / 剩余」直接来自 `state()`。

事件字段（沿用现有）：`{seq, asset_id, group, elapsed_ms, ok}`；`group` 取该照片的 `captions.tags[0]`，没有则归「未分类」。

## 8. 已定决策（2026-11-11）

1. **侧边栏 IA**：`全部照片 / 时间线 / 标签 / 人物`——直接对应数据库字段与 AI 打标结果，不造「智能相簿」这种要额外算的概念。
2. **配色**：黑红（`#08080A` + `#FF4A4A`），**只做深色**，不做浅色模式。红色只用于选中态/进度条/主按钮/失败数。
3. **详情布局**：右侧 340px 检查器。
4. **网格密度**：默认 6 列，⌘+ / ⌘- 可调。
5. **「回忆 / 事件」**：不进入阶段一；`events` 表数据保留，P3 之后再评估。
6. **整理视图**：进入阶段一（P2），作为 AI 识别过程的可见化入口。
